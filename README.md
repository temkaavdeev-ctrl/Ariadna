# Ариадна

Личная автономная команда Артёма: память, планирование, приоритеты, декомпозиция, ресёрч, забота. Не сервис и не список дел — спутница с характером. Родитель — организм Bookz; генофонд общий, данные — раздельные.

## Живёт здесь

- **Supabase-проект** `ariadna` (ref `bhpkuhvjutxhzcembctm`, eu-central-1, free tier) — истина. Файлы в репо — зеркало.
- `supabase/migrations/` — зеркала применённых миграций (схема + органы).
- Генезис (конституция, модель владельца, план самосборки, гены) — в `Ariadna-private/genesis/` и в таблице `files` обоих проектов (Bookz — родовой пакет, ariadna — своя копия).

## Устройство (неделя 1)

- **Тенантность с первого байта**: каждая таблица данных несёт `owner_id` + RLS (`my_owner_id()` по `auth.uid()`); anon отозван полностью. Уроки и файлы (`lessons`, `files`) — общее ремесло, без owner_id.
- **Память**: `owner_signals` (симулякр владельца), `episodes`, `chronicle` (победы, не долги), `relationship_memory`, `decisions` (журнал + «почему не иначе»). Уровни чувствительности `open/private/intimate`; intimate никогда не эмбеддится.
- **Шина**: `bus` + `task_dispatch`/`task_close` (с intent — намерением, не только формулировкой).
- **Telegram**: один бот на всех владельцев (`tg_bot` — глобальный оффсет, `tg_users` — привязка чатов по инвайт-коду). `tg_inbound_tick` ежеминутно: бинд, команды (`/status`, `/симулякр`, «симулякр: поправка…»), текст → задача. `tg_digest_tick` — утренний бриф.
- **Эмбеддинги**: Voyage (free tier, батч 6, тик 1/мин) → `owner_check` (сверка рамки с позициями владельца), `mem_recall` (semantic по решениям/эпизодам).
- **Апоптоз**: задача с `postpone_count ≥ 4` → бережный вопрос «убить, переродить или не время?».

## Секреты

Только в Supabase Vault (никогда в код/репо): `tg_bot_token`, `voyage_api_key`, `groq_api_key`, позже `todoist_token_<owner>`. Все органы — `SECURITY DEFINER` с pinned `search_path`, `EXECUTE` отозван у anon.
